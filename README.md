# neuron-test-bench

A Python tool that reads **oscilloscope CSV exports** and measures a spiking
neuron's output — built to test the low-power analog spiking-neuron board for
the Spring 2027 Honors College research project *"Spiking artificial neuron"*
(Prof. Walter Daniel Leon-Salas): a coin-cell-powered analog board emulating a
spiking neuron, with potentiometers to adjust synaptic weights by hand, a
proof-of-concept prototype to be tested, and a small network to control a
robot. Before a board can drive a robot, you need to prove it spikes the way
you designed it to — this is the bench that proves it.

## What it does

- **CSV parser** (`neuron_test_bench/parser.py`) — tolerant of a header line
  and `time, voltage` columns, with units in the header if present
  (`Time (ms), Voltage (mV)`, `time_s, voltage_V`, …); also works with no
  header at all (assumes seconds / volts), comment lines, and extra columns.
- **Spike detection** (`neuron_test_bench/analysis.py`) — upward threshold
  crossing, then the peak within the refractory window; crossings closer
  together than the refractory period (default 2 ms) are merged.
- **Metrics** — spike count, mean firing frequency, mean/median inter-spike
  interval (ISI), ISI standard deviation and coefficient of variation
  (jitter), mean spike amplitude (peak − baseline), mean spike width
  (full width at half maximum, by linear interpolation).
- **Pass/fail report** (`neuron_test_bench/report.py`) — checks the measured
  values against an expected spec (default: 15–25 Hz, 60–100 mV amplitude,
  ISI CV ≤ 0.15, width 0.5–2.5 ms, ≥ 5 spikes) and writes a text report and
  a one-row-per-trace CSV. The spec is customisable per board revision.

## How to run

Requires Python 3.10+ and NumPy only (`matplotlib` is needed only for the
optional `--plot` flag).

```bash
# Regenerate the sample oscilloscope traces (optional — data/ is included)
python3 generate_data.py

# Demo: measure all four sample traces, print the reports, write
# reports/report.txt and reports/report.csv
python3 demo.py

# Also save a plot per trace under plots/ (PNG; not part of the repo)
python3 demo.py --plot

# Run the tests (pytest is not installed here, so unittest is used)
python3 -m unittest discover -s tests -v
```

Analyse your own export from Python:

```python
from neuron_test_bench import load_trace, compute_metrics, check_pass_fail

times, volts = load_trace("my_scope_export.csv")   # seconds, volts
metrics = compute_metrics(times, volts, threshold_v=0.04)
passed, checks = check_pass_fail(metrics)
print(passed, metrics["frequency_hz"], metrics["amplitude_mean_mv"])
```

## Sample data

All traces are 2.0 s long, sampled at 20 kHz, with Gaussian spikes
(σ = 0.5 ms → FWHM 1.18 ms), generated by `generate_data.py`:

| File | Ground truth |
|---|---|
| `data/good_neuron.csv` | 40 spikes, exactly 20 Hz, 80 mV, 1 mV RMS noise |
| `data/noisy_neuron.csv` | ~40 spikes, ~20 Hz, jittered ISIs (σ = 12 ms), 70–90 mV, 5 mV RMS noise |
| `data/no_spikes.csv` | Baseline + 2 mV RMS noise, no spikes |
| `data/failing_neuron.csv` | 16 spikes, 8 Hz, 45 mV, jittered ISIs |

## Headline results (measured by running `demo.py`)

| Trace | Spikes | Freq | ISI mean | ISI CV (jitter) | Amplitude | Width (FWHM) | Verdict |
|---|---|---|---|---|---|---|---|
| good_neuron | 40 | 20.00 Hz | 50.0 ms | **0.0012** | **80.66 mV** | **1.17 ms** | **PASS** |
| noisy_neuron | 40 | 20.00 Hz | 45.2 ms | 0.2193 | 85.62 mV | 1.08 ms | FAIL — jitter only (CV 0.22 > 0.15 limit) |
| no_spikes | 0 | 0.00 Hz | — | — | — | — | FAIL (gracefully: 0 spikes, no crash) |
| failing_neuron | 16 | 8.00 Hz | 128.2 ms | 0.1124 | 46.7 mV | 1.14 ms | FAIL — 8 Hz < 15 Hz floor, 46.7 mV < 60 mV floor |

On the good trace the tool recovers the known ground truth almost exactly:
20.00 Hz vs 20 Hz nominal, 80.66 mV vs 80 mV, 1.17 ms width vs 1.18 ms
FWHM — and it cleanly separates the regular trace (CV 0.001) from the
jittered one (CV 0.22).

## Tests

**16 tests, 16 passed** (`python3 -m unittest discover -s tests`, ~0.9 s).
Covered: parser reads all sample CSVs, header units (ms/mV) and headerless
(s/V) files, empty-file error; spike detection finds the known count (40) in
synthetic data and merges crossings inside the refractory window; frequency /
ISI / amplitude / width are within tolerance of known ground truth; jitter is
low for regular spikes (CV < 0.05) and higher for jittered spikes
(CV > 0.10); pass/fail passes the good trace and fails the bad, noisy
(jitter-only) and no-spike traces; the no-spike trace reports 0 spikes and
`nan` metrics instead of raising; the acceptance spec is customisable.

## Research-application talking point

> "Built a test bench that validates a coin-cell spiking-neuron board from
> oscilloscope exports — it recovers firing rate, amplitude and spike width
> to within ~1% of ground truth on synthetic traces and automatically
> pass/fails a board against spec (e.g. 20.00 Hz, 80.7 mV, 1.17 ms FWHM,
> ISI CV 0.001 on a good board), so prototype bring-up becomes a repeatable
> measurement instead of eyeballing waveforms."
